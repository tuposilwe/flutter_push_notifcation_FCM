## 1. What this app is

A minimal Flutter app that demonstrates Firebase Cloud Messaging (FCM) end to end: requesting
notification permission, obtaining a device token, subscribing to a topic, and receiving messages
in all three app lifecycle states — foreground, background, and terminated.

## 2. How Firebase Cloud Messaging works (the big picture)

```
┌─────────────────────┐        ┌──────────────────┐        ┌──────────────────────┐
│  Firebase Console    │  send  │   FCM backend    │  push  │   Device (this app)  │
│  or Admin SDK/API    │───────▶│  (Google's relay)│───────▶│                       │
│  "send to topic:news"│        │                  │        │  APNs (iOS) / FCM SDK │
└─────────────────────┘        └──────────────────┘        └──────────────────────┘
                                                                       │
                                                     ┌─────────────────┼─────────────────┐
                                                     ▼                 ▼                 ▼
                                              app in FOREGROUND  app in BACKGROUND   app TERMINATED
                                              onMessage listener  system tray, then   system tray, then
                                              → we show a local  onMessageOpenedApp  getInitialMessage()
                                              notification        on tap             on next cold start
```

FCM never shows a notification banner while the app is in the foreground — that's why the app
uses `flutter_local_notifications` to display one manually when `onMessage` fires. In
background/terminated states, the OS shows the system notification automatically from the payload.

## 4. What happens when the app starts (`lib/main.dart` walkthrough)

### 4.1 Initialization

```dart
await Firebase.initializeApp(options: DefaultFirebaseOptions.currentPlatform);
FirebaseMessaging.onBackgroundMessage(firebaseMessagingBackgroundHandler);
await _initLocalNotifications();
```

Firebase is initialized with the config generated for the current platform. The background
handler is registered *before* `runApp()` — it must be a top-level function because Android/iOS
run it in a separate isolate when a message arrives while the app isn't running.

### 4.2 Requesting permission & getting the token

```dart
final settings = await _messaging.requestPermission(alert: true, badge: true, sound: true);
final token = await _messaging.getToken();
```

The token uniquely identifies this app install on this device. It's what you'd send to your own
backend to target a specific user, and it's what the Firebase Console's "test message" feature
uses. It's shown in the app UI with a copy button.

### 4.3 Listening for messages

| Listener | Fires when | What the app does |
|---|---|---|
| `FirebaseMessaging.onMessage` | Message arrives while app is open (foreground) | Logs it in the list + shows a local notification |
| `FirebaseMessaging.onMessageOpenedApp` | User taps a notification that arrived while backgrounded | Logs it in the list |
| `_messaging.getInitialMessage()` | App is cold-started by tapping a notification | Logs it in the list |
| `firebaseMessagingBackgroundHandler` | Message arrives, app backgrounded/terminated | Runs in a separate isolate; just re-inits Firebase (OS shows the notification itself) |

### 4.4 Topics

Topics let you broadcast to every subscribed device without tracking individual tokens. Tapping
**Subscribe** in the app calls `_messaging.subscribeToTopic('news')` (or whatever you typed in the
Topic field). **Unsubscribe** calls the mirror method.

## 5. Platform-specific setup explained

### 5.1 Android

- **POST_NOTIFICATIONS permission** — required on Android 13+ or notifications are silently blocked.
- **Notification channel** (`high_importance_channel`) — Android 8+ requires every notification to
  belong to a channel; created at startup and referenced in the manifest as the default FCM channel.
- **Core library desugaring** — `flutter_local_notifications` uses Java 8+ APIs that need
  desugaring support on older Android API levels; enabled in `build.gradle.kts`.

### 5.2 iOS

- **UIBackgroundModes: remote-notification** — lets the app wake briefly to process a push while backgrounded.
- **Deployment target 15.0** — required by the version of `firebase_core` used here.
- **Push Notifications capability (not yet done)** — see [section 8](#8-whats-still-needed-from-you).

## 6. How to test the app

### 6.1 Run it

```
flutter run
```

Grant the notification permission prompt, then note or copy the device token shown on screen.

### 6.2 Subscribe to a topic

Type a topic name (default `news`) and tap **Subscribe**. The button changes to "Unsubscribe" once
it succeeds.

### 6.3 Send a test notification — by topic

1. Open [Firebase Console → Messaging](https://console.firebase.google.com/project/pushnotification-4281b/messaging).
2. **New campaign → Notifications**.
3. Enter a title and body.
4. Under **Target**, choose **Topic** and enter the exact same topic name used in the app.
5. **Review** → **Publish**.

### 6.4 Send a test notification — by device token

In the same compose screen, use the **"Send test message"** button and paste the token copied from
the app. This targets one specific device/install regardless of topic subscription — useful for
quick single-device checks.

> **Expected results**
> - App open (foreground): notification appears in the app's own "Received messages" list, plus a local notification.
> - App backgrounded: standard system notification appears; tapping it opens the app and logs "opened from background".
> - App killed: same as above, logged as "opened from terminated" on next launch.

## 7. Issues hit during setup, and the fixes

| Problem | Cause | Fix |
|---|---|---|
| `flutterfire configure` crashed with a Ruby `xcodeproj` LoadError | macOS's bundled system Ruby (2.6) can't build the native gem extension needed by the CLI's Xcode-project editing step | Installed a modern Ruby via Homebrew and the `xcodeproj` gem under it, then re-ran configure with that Ruby first on PATH |
| `flutterfire configure` initially failed with "Firebase CLI not found" | The FlutterFire CLI shells out to the official Firebase CLI, which wasn't installed | Installed it via `brew install firebase-cli` |
| Android build failed: "flutter_local_notifications requires core library desugaring" | The plugin depends on desugared Java 8+ APIs not available by default on older Android targets | Enabled `isCoreLibraryDesugaringEnabled = true` and added the `desugar_jdk_libs` dependency |
| Android build failed with a `jlink` error inside `core-for-system-modules.jar` | The system's default JDK (Zulu 26) is too new / incompatible with the Android Gradle Plugin's JDK-image transform | Pointed Flutter at Android Studio's bundled JDK 21 via `flutter config --jdk-dir=...` (persists for all future builds on this machine) |
| One build failed on `stripDebugDebugSymbols` | Two Gradle builds ran concurrently and raced on the same output directory (not a real bug) | Re-ran cleanly; not seen again |

## 8. What's still needed from you

> **iOS Push Notifications capability** — the simulator log shows
> `"no valid aps-environment entitlement string found for application"`. Real push delivery on a
> physical iPhone requires enabling the **Push Notifications** capability in Xcode, which needs
> your own Apple Developer account/team. This can't be done without your login, so it wasn't
> automated.
>
> **To fix:** open `ios/Runner.xcworkspace` in Xcode → select the *Runner* target → *Signing &
> Capabilities* → select your Team → *+ Capability* → *Push Notifications*. Android needs no
> equivalent step.
